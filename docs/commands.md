# Commands

What each command of the workspace does. `CLAUDE.md` lists the commands themselves; this page explains them. It was moved out of `CLAUDE.md` on Nov 12, 2026 to keep that file short.

`serve SCENARIO --seat allied=player --seat japanese=script` holds a game open and takes one JSON request a line on standard input (decision 0050). `mcp SCENARIO --seat allied` serves the same game and tools as a Model Context Protocol server on standard input and output, and `play --game FILE ... TOOL [ARGUMENTS]` makes one call to it and exits, keeping the game as a file of the calls made (decision 0051); `play` alone prints how. `.mcp.json` starts that server for Claude Code in this folder, on the full slice with the player as the Allied side (decision 0051, added on the designer's word); edit its last arguments for another scenario or seat. `run --save FILE` writes a saved game (the scenario's name, the seed, each day's orders and the daily hashes); `replay FILE` runs it again and fails on the first day whose hash differs, and refuses a scenario or data file that has changed; `hash` prints the daily hashes only (decision 0043). `events SCENARIO_OR_SAVE --unit HANDLE [--day N]` is the umpire's question to a finished run: it prints every event that names a ship, task force, air group, base or contact in the text `run --events` prints (a ship's task force's events too, marked `via`), and `events ... --why EVENT` prints one event and its causes down to orders as a tree (decision 0052, item 9). `export` runs a scenario exactly as `run` does and writes it as one replay file for the viewer (decision 0018); it also takes `--seed N` and `--labels data/map/south_pacific_anchors.csv`. `batch` runs a scenario over many seeds (`--runs N`, default 1000, `--first-seed S`, default 1, `--label TEXT` to record the caller's name for the engine, such as a revision; decision 0057) and writes one summary file of losses per side, per ship and per run, and, for each run, the counts step 2's measures read: hits by ship and weapon, gun and torpedo fire by side, systems out, aircraft lost by group and cause, aircraft ready at the end of each day, claims by side, attacks, escorts, break-offs and base supply (decision 0062; the file is version 2). It is the umpire's file and shows the truth. `run`, `replay`, `hash`, `events`, `export` and `batch` take `--reference DIR`: the scenario's reference files (ship classes, port sizes, aircraft types, and the search, surface combat, air combat, air upkeep, fatigue and base supply figures) are then read by file name from DIR, in place of where the scenario names them, and one that is not in DIR is an error; the map is read where the scenario names it. `--reference data/reference/step1` runs a scenario on the figures frozen at the end of step 1, which the hand-calculation tests use. A saved game or a batch made with it records DIR's files and their hashes as its inputs, and `replay` and `events` on that game need the same `--reference` and the same files; without it they refuse, saying the scenario now names different data files. `serve`, `mcp` and `play` do not take it. Open `viewer/index.html` in a browser and pick the file. `node viewer/check.js viewer/replays/*.json` checks replays against the page's own rebuild.

The map tool also has `locate --lat --lon`, `path --from q,r --to q,r`, `sides --hex q,r` (a hex's closed sides and neighbours), `water --lat --lon` (why a position's hex has the water it has) and `generate`, which rebuilds `data/map/south_pacific.csv` from the Natural Earth files under `references/` (the exact command is in the file's header). `generate --anchors data/map/south_pacific_anchors.csv` applies the listed anchorages (decision 0017, decision 6); without it hexes keep their largest body of water. `render` draws `#` land, `+` coast, `%` coast with a closed side toward water and `.` sea, each row labelled with its r and the q of its first hex.

`oob-derive` derives ship classes for a list of real ships from `data/oob` (decision 0020). A ship list may name working assumptions (unknown radar means none, decision 0019; main-gun ammunition not limiting, decision 0023; surface weapons not modelled, decision 0029), may ask for the air figures and may list aircraft types to derive, and the rules file names every exception. With any problem it writes nothing and lists every problem; `--check` only reports; `--facts DIR` reads another facts directory.
