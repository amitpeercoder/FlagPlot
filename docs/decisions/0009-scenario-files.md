# 0009: Scenario files and saved games

Status: settled.

## The gap in the spec

The spec says a scenario is a TOML file with the starting state, scripted orders and seed, and that a saved game is the starting state, the seed and the orders per day. It gives no file layout.

## Decisions

- **A scenario file is also the saved-game format, for now.** It holds everything a replay needs. A separate format for games played interactively is not needed until the agent server exists.
- **Layout:** top-level name, seed, day count and paths to the map and ship class files, then lists of bases, task forces, ships and orders. See `data/scenarios/01_transit.toml`.
- **Every scenario file must say whether it is placeholder data.** The field is required.
- **Maps are TOML:** rectangular regions of identical hexes, then single-hex overrides. The spec does not give a map format. This one is compact for a placeholder. The real map will probably need one row per hex, generated by a tool.
- **Ship classes are CSV,** as the spec says, with `#` comment lines allowed.
- **Quantities are whole numbers or decimal strings.** TOML floats are rejected.
- **Unknown fields are an error,** so a typo in a field name cannot be silently ignored.

## Not done yet

- Hex latitude and longitude. The spec asks for them for rendering. The placeholder map has no real geography, so they are left out until the real map is drawn. *(Nov 14, 2026: the map has them, decision 0017)*
- Most ship class fields the spec lists: displacement, guns, torpedoes, anti-aircraft, armour, aircraft capacity, cargo and troop capacity.
- Aircraft types and weapons. *(Nov 14, 2026: aircraft types came with decisions 0025 to 0029)*
- JSON schemas for orders and observations, which the agent interface needs. *(Nov 14, 2026: built by decision 0048, item 11)*
