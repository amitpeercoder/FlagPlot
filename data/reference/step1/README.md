# Frozen figures of step 1

A copy of every figures file a scenario names, as they stood at the end of step 1 (Nov 12, 2026). The hand-calculation tests in `tests/` read these and not the live files in `data/reference`, for the length of step 2, so that tuning a live figure does not break a calculation worked on the figures of the day (`docs/step2-spec.md`, "Tests while figures move"; decided by the designer, item 3).

- **Do not edit.** Each file's header says so. The one exception: a rule that adds a figure adds it here too, with its first value. `crates/sim-data/tests/frozen_figures.rs` fails if a frozen file lacks a key or column its live file has, or if a live figures file has no copy here.
- **What is here:** port sizes, ship classes and aircraft types (including the derived files `ship_classes_savo_island.csv`, `ship_classes_eastern_solomons.csv`, `aircraft_types_eastern_solomons.csv` and `aircraft_types_rabaul_guadalcanal.csv`), and the search, surface combat, air combat, air upkeep, fatigue and base supply figures. Derived and placeholder tables are frozen too, so that every input of a hand calculation is in this one place and a change to the derivation rules cannot move it. The `.sources.csv` and `.ships.csv` files that record a derivation are not read by the loader and are not copied. The map is not a figures file and is not copied.
- **How a scenario reads them:** `sim_data::LoadOptions { reference_root: Some(dir) }` with `Scenario::load_with`, or `--reference DIR` on `sim-cli`. A reference file the scenario names is looked up by its file name in that directory; one that is missing is an error.
- **What they do not do:** the run baselines (`crates/sim-cli/tests/run_baseline`), `batch` and the recorded games follow the live figures. A test that passes here proves the rules compute what the hand calculation says, on known figures. It says nothing about the figures in use; that is `validate`'s job.
