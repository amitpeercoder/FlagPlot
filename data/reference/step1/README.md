# Frozen figures of step 1

A copy of every figures file a scenario names, as they stood at the end of step 1 (Nov 12, 2026). The hand-calculation tests in `tests/` read these and not the live files in `data/reference`, during step 2 and after it (the designer ruled on Nov 13, 2026, at the close, "No, keep them frozen": `docs/step2-spec.md`, the close, item 15), so that tuning a live figure does not break a calculation worked on the figures of the day (`docs/step2-spec.md`, "Tests while figures move"; decided by the designer, item 3).

- **Do not edit.** Each file's header says so. The one exception: a rule that adds a figure adds it here too, with the value that leaves step 1's results as they were where there is one, and otherwise its first value. The two figures of decision 0059, 6a (`crew_recovered_over_own_base`, `crew_recovered_beside_own_force`) are "1" here: every patrol pilot recovered, which is step 1's rule; the live file has 0.6 and 0.95. The three strengths of experience (decision 0064) are "0" here, the value at which the rule does nothing, and "0.25" in the live file. The three reach figures keep their values, since with no reach order they change nothing. `anti_aircraft_before_attack_share` (decision 0079) is "1" here: every shot of the guns worked before the attack, which is step 1's rule; the live file has 0. `patrol_drawn_off_share` (decision 0080) is "1" here: the escorts draw the patrol off the bombers one for one, which is step 1's rule; the live file has 0. `patrol_before_attack_share` (decision 0087) is "1" here: every shot of the patrol at the bombers worked before the attack, which is step 1's rule; the live file has 0.4. `crates/sim-data/tests/frozen_figures.rs` fails if a frozen file lacks a key or column its live file has, or if a live figures file has no copy here.

- **What is here:** port sizes, ship classes and aircraft types (including the derived files `ship_classes_savo_island.csv`, `ship_classes_eastern_solomons.csv`, `aircraft_types_eastern_solomons.csv` and `aircraft_types_rabaul_guadalcanal.csv`), and the search, surface combat, air combat, air upkeep, fatigue and base supply and ground figures. Derived and placeholder tables are frozen too, so that every input of a hand calculation is in this one place and a change to the derivation rules cannot move it. The `.sources.csv` and `.ships.csv` files that record a derivation are not read by the loader and are not copied. The map is not a figures file and is not copied.
- **Added in step 2:** `ship_classes_cape_esperance.csv`, the derived classes of Cape Esperance, copied here when they were first derived (Nov 13, 2026), by the architect's ruling under "Tests while figures move", 6: what step 2 adds goes into the frozen copy too, so that scenario 17's test runs on the frozen figures like the others (decision 0072). It is a copy of the file as first derived, and a later re-derivation of the live file does not reach it.
- **How a scenario reads them:** `sim_data::LoadOptions { reference_root: Some(dir) }` with `Scenario::load_with`, or `--reference DIR` on `sim-cli`. A reference file the scenario names is looked up by its file name in that directory; one that is missing is an error.
- **What they do not do:** the run baselines (`crates/sim-cli/tests/run_baseline`), `batch` and the recorded games follow the live figures. A test that passes here proves the rules compute what the hand calculation says, on known figures. It says nothing about the figures in use; that is `validate`'s job.
