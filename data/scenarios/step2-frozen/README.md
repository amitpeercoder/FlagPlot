# Frozen scenarios of step 2

Copies of scenarios as they stood before step 2 changed their orders, the counterpart of the frozen figures in `data/reference/step1` (`docs/step2-spec.md`, "Tests while figures move", 9; decisions 0073 and 0075). The principle: frozen figures go with frozen scenarios, live scenarios with live figures.

- **What is here:** `05_eastern_solomons.toml`, `07_full_slice.toml` and `08_soak.toml`, scenarios 5, 7 and 8 as they stood on main with decision 0063's orders, before decision 0073 set the Japanese search from the record. Each starts with a "FROZEN COPY" header; below it the only difference from the file on main is that the paths to the map and the reference files are one folder deeper.
- **Who reads them:** every test that runs scenario 5, 7 or 8 on the frozen figures, hand calculation or not, including the agent's tests (`crates/sim-agent/tests`). The reason: a live order may name a distance the frozen ceilings refuse (Chikuma's floatplanes are ordered to the 330 miles flown, and the frozen E13A1's search range is 253), and the refused order would silently drop out of the test. The doc comment of every test that reads a copy says it runs on the frozen copy. A test that runs a live scenario on the live figures reads the live file and follows live data. Nothing that plays the game, no batch, no baseline and no export reads a copy; `data/scenarios/*.toml` does not match them, so the scenario loops of CI and the tests skip them.
- **Limits:** one frozen copy for a scenario and no more. A copy changes only with a rule change's new hand calculation, written by the architect. Nothing remakes it otherwise, and a change to the live scenario's data does not reach it.
- **What a test on it proves:** that the rules compute what the test says, on known orders and known figures. It says nothing about the live scenario: the run baselines (`crates/sim-cli/tests/run_baseline`) and `validate` cover that.
